# ЛР1. Ручний backpropagation (NumPy) і його перевірка

Мережа: `X → Linear(4, 8) → ReLU → Linear(8, 3)`, втрата — крос-ентропія, усереднена за об'єктами. Усі обчислення у float64.

## Відтворення

```bash
cd lab1
uv sync
uv run python main.py            # правильна реалізація (за замовчуванням): пп. 2 і 3
uv run python main.py --faulty   # дослід 4: градієнт за логітами без ділення на N
```

Версії зафіксовано в `pyproject.toml` (`numpy==2.4.4`, `scikit-learn==1.8.0`, `torch==2.14.1`, Python 3.12) та `uv.lock`.

Дані: train 105 (по 35 на клас), test 45 (по 15). Основні перевірки — на всіх 105 train-об'єктах і початкових параметрах.
Ініціалізація: новий `default_rng(0)`; спершу `W1 ~ N(0, √(2/4))` розміром 4×8, потім `W2 ~ N(0, √(2/(8+3)))` розміром 8×3; `b1`, `b2` — нулі.

## 1. Формули

Позначення: N = 105 — розмір вибірки, `X ∈ R^{N×4}`, `Y ∈ R^{N×3}` — one-hot мітки.

**Прямий прохід**

- `Z1 = X·W1 + b1`  (N×8)
- `A1 = ReLU(Z1) = max(Z1, 0)`  (N×8)
- `Z2 = A1·W2 + b2`  (N×3) — логіти

**Стабільна втрата.** Для кожного рядка `m = max_j Z2[i,j]`,
`log_softmax(Z2)[i,j] = (Z2[i,j] − m) − log Σ_k exp(Z2[i,k] − m)`,
`L = −(1/N) Σ_i log_softmax(Z2)[i, y_i]`.
Зсув на максимум не змінює значення, але виключає переповнення `exp`.

**Зворотний прохід** (P = softmax(Z2), N×3)

1. `dZ2 = (P − Y) / N`  (N×3)
2. `dW2 = A1ᵀ · dZ2`  (8×3)
3. `db2 = Σ_i dZ2[i,:]`  (3)
4. `dA1 = dZ2 · W2ᵀ`  (N×8)
5. `dZ1 = dA1 ⊙ 1[Z1 > 0]`  (N×8)
6. `dW1 = Xᵀ · dZ1`  (4×8)
7. `db1 = Σ_i dZ1[i,:]`  (8)

Обґрунтування: для крос-ентропії з softmax `∂ℓ_i/∂Z2[i,:] = P[i,:] − Y[i,:]`; множник `1/N` — від усереднення за об'єктами. Афінний шар `Z = A·W + b` дає `dW = Aᵀ dZ`, `db = Σ dZ`, `dA = dZ Wᵀ`. Похідна ReLU — індикатор `Z1 > 0` (у точці 0 прийнято 0, як і в PyTorch).

**Розмірності**

| Масив | Розмір | Масив | Розмір |
|---|---|---|---|
| X | 105×4 | dZ2 | 105×3 |
| Z1, A1 | 105×8 | dA1, dZ1 | 105×8 |
| Z2, P | 105×3 | **dW1** | **4×8** |
| W1, W2 | 4×8, 8×3 | **db1** | **8** |
| b1, b2 | 8, 3 | **dW2** | **8×3** |
| | | **db2** | **3** |

**Збережені проміжні значення (cache):** `X` (потрібен для dW1), `Z1` (маска ReLU для dZ1), `A1` (потрібен для dW2), `Z2` (з нього відновлюється softmax). Ваги `W2` беруться з параметрів для dA1.

## 2. Звірка з PyTorch

Параметри скопійовано в `torch.nn.Linear` з транспонуванням (PyTorch зберігає ваги як (out, in)); градієнти транспоновано назад. Критерій: `|a − b| ≤ 1e-12`, усі значення скінченні (перевірено: так).

Втрата NumPy: `1.4562007801142816`
Втрата PyTorch: `1.4562007801142818`

|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт dW1 | 5.551e-17 | так |
| Градієнт db1 | 3.816e-17 | так |

## 3. Чисельне диференціювання

Центральна різниця `g = (L(θ+ε) − L(θ−ε)) / (2ε)`, ε = 1e-6, початкові ваги, 105 об'єктів; значення параметра відновлюється після кожної перевірки. Критерій: `|g_num − g_manual| ≤ 1e-7`.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0,0] | −1.9920184331e-02 | −1.9920184391e-02 | 6.034e-11 | так |
| b1[0] | −7.0566111584e-02 | −7.0566111621e-02 | 3.633e-11 | так |
| W2[0,0] | 1.3523020861e-01 | 1.3523020870e-01 | 9.218e-11 | так |
| b2[0] | 8.5521644842e-02 | 8.5521644988e-02 | 1.460e-10 | так |

Різниці ~1e-10 — типова похибка центральної різниці при ε=1e-6 (округлення ~1e-16/ε), тож критерій 1e-7 виконується із запасом.

## 4. Дослід із навмисною помилкою

Помилка: у `backward(..., faulty=True)` прибрано ділення на N у `dZ2` (`dZ2 = P − Y`). Функція втрат, дані та параметри не змінювалися, оновлень ваг немає.

**Прогноз (записано до запуску)**

1. *Втрата не зміниться:* forward і формула L не залежать від backward.
2. *Градієнти:* `dZ2` зросте в N = 105 разів, а всі подальші кроки (2–7) лінійні за `dZ2`, а маска ReLU від нього не залежить. Тому всі чотири градієнти збільшаться рівно в 105 разів (нулі залишаться нулями; ненульові — ×105).
3. *Які перевірки виявлять:* звірка втрати з PyTorch пройде; звірка градієнтів з PyTorch провалиться для всіх чотирьох (різниця ≈ 104·|g|, тобто порядку 10¹); чисельна перевірка провалиться для всіх чотирьох параметрів (backward ≈ 105·g_num).

**Результат** (`uv run python main.py --faulty`)

| Величина | Макс. абс. різниця NumPy / PyTorch | Пройдено |
|---|---|---|
| Втрата | 2.220e-16 | так |
| dW1 | 1.852e+01 | НІ |
| db1 | 1.564e+01 | НІ |
| dW2 | 3.419e+01 | НІ |
| db2 | 1.120e+01 | НІ |

Відношення `NumPy/PyTorch` на ненульових елементах: мінімум = максимум = 105.000000 для всіх чотирьох градієнтів.

| Параметр | backward() | Чисельна похідна | Абс. різниця | Пройдено |
|---|---|---|---|---|
| W1[0,0] | −2.0916193547e+00 | −1.9920184391e-02 | 2.072e+00 | НІ |
| b1[0] | −7.4094417164e+00 | −7.0566111621e-02 | 7.339e+00 | НІ |
| W2[0,0] | 1.4199171904e+01 | 1.3523020870e-01 | 1.406e+01 | НІ |
| b2[0] | 8.9797727084e+00 | 8.5521644988e-02 | 8.894e+00 | НІ |

**Зіставлення з прогнозом:** збіглося повністю. Втрата не змінилась; усі градієнти точно ×105 (напр. `−2.0916/105 = −0.019920`); обидві перевірки виявили помилку. Важливо: перевірка лише втрати цю помилку не виявляє — потрібна саме перевірка градієнтів. Практичний наслідок: така помилка еквівалентна збільшенню learning rate у N разів, тому навчання могло б розходитися, хоча «код працює». Після досліду правильна реалізація відновлена (`faulty=False` за замовчуванням).

## Висновки

- Ручний backprop збігається з PyTorch autograd на рівні машинної точності (~1e-16) і з чисельною похідною на рівні ~1e-10.
- Стабільний log-softmax (зсув на максимум) дає ту саму втрату, що й `F.cross_entropy`.
- Помилку масштабу градієнта виявляють і порівняння з autograd, і чисельна перевірка, а перевірка значення втрати — ні.
- Поширена пастка при порівнянні з PyTorch — розташування ваг `(out, in)` в `nn.Linear`: потрібне транспонування.
